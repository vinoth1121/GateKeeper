# GateKeeper — Threat Model

Rate-limiting gateway for LLM APIs: per-tenant token-rate policies enforced in
front of a fixed upstream. Stride: every threat below has a concrete mitigation
that is implemented (or gated — see `docs/evidence/gates.md`) in the codebase,
not a recommendation.

| # | Threat | Mitigation |
|---|---|---|
| 1 | **Spoofed `X-Forwarded-For`.** A client forges XFF to rotate its apparent source IP and evade per-IP limits. | **Trusted-proxy-only, rightmost-untrusted.** XFF is honored only when the direct peer is in `GATEKEEPER_TRUSTED_PROXIES` (IPs/CIDRs from env). The client IP is then taken as the rightmost XFF entry **not** in the trusted list — the standard rightmost-untrusted algorithm. Untrusted peers get their socket address, and their XFF is ignored entirely. |
| 2 | **API-key brute force / enumeration.** Attackers spray keys to find valid tenant credentials, or time responses to distinguish "key exists" from "malformed". | Keys are stored as **SHA-256 hashes at rest**, never plaintext. Lookup and comparison are **constant-time** (hash first, compare digests — no early-exit string compare). Every failure returns **uniform 401s**: same status, same body, same headers, same timing profile whether the key is unknown, revoked, or malformed — no oracle for enumeration. |
| 3 | **CEL policy injection.** A tenant or attacker crafts a CEL expression that loops forever, allocates unboundedly, or reads fields outside its tenant scope. | Policies are **compiled and typechecked at publish time** — a policy that fails compile never lands; type errors come back with **error positions**, not "invalid policy". Publish enforces **size and evaluation-cost limits**, and CEL is **non-Turing-complete** (no recursion, no unbounded loops), so worst-case cost is bounded by construction. Every evaluation runs inside a **sandbox wrapper that forces `tenant.id == 'demo-sandbox'`** for sandbox publishes AND bounds the numeric limits a policy may set — a policy cannot grant itself a bigger quota than the sandbox ceiling. Real (non-sandbox) publishes require the **admin key**. |
| 4 | **Redis Pub/Sub loss.** A config-change broadcast is dropped (dead subscriber, connection blip), so a node keeps enforcing a stale policy. | Every policy/config version is **monotonically versioned**. Pub/Sub is the fast path, but every node also runs **interval polling** as a fallback: a node that missed a broadcast converges to the latest version within one polling interval. Subscribers ignore any version lower than what they already hold. |
| 5 | **Redis outage.** Redis is down, slow, or partitioned (toxiproxy simulates all three) — does the gateway become an open door or a brick? | **Resilience4j circuit breaker around all Redis calls** (breaker + time limiter, BOM 2.4.0). Behavior depends on the tenant's configured `failMode`: **OPEN_LOCAL** — the node falls back to a local backstop computed as `policyLimit / max(1, liveNodeCount)`, where `liveNodeCount` comes from **TTL heartbeats** (nodes renew a heartbeat key with a TTL; unreachable/stale nodes fall out of the count), and the local count **starts from the last-known token state** captured while Redis was reachable. **CLOSED** — deny: a tenant that said "strict" gets 503/429, never an unmetered pass. No configuration = silent fail-open. |
| 6 | **Lease overshoot.** The leasing scheme lets a burst admit more tokens than the global limit allows. | The bound is **documented and tested**: global usage may exceed the limit by at most `nodes x leaseSize` (see `docs/decisions.md` §5). **Strict policies bypass leasing entirely** and hit the global bucket. Tests assert **conservation** — total admitted across nodes never exceeds limit + bound, and never exceeds limit for strict tenants. Tokens lost to a crashed node are acceptable under-use. |
| 7 | **Metrics cardinality attack.** A tenant sprays unique label values (tenant IDs in a label, per-key tags) and blows up Prometheus memory / scrape size. | Metric labels are a **closed set**: `tier`, `rule`, `decision`, `reason` only — never tenant IDs, keys, or URLs. Anything per-tenant that must be visible is served as **top-N aggregates via the admin JSON endpoint** (computed on demand, bounded N), not as time series. |
| 8 | **Oversized requests/headers.** Giant headers or bodies exhaust the 512 MB JVM before rate limiting even runs. | Enforced limits at the servlet layer on request size, header count, and per-header value length; over-limit requests are rejected with 413 before any per-tenant work, CEL evaluation, or upstream connection. |
| 9 | **SSRF via the proxy.** An attacker makes the gateway fetch an internal address. | The gateway proxies only **fixed, configured upstreams** (`GATEKEEPER_UPSTREAM_URL` from env); there are **no user-supplied URLs anywhere** in the routing or policy model. CEL policies select among configured upstreams by name, never by URL. |
| 10 | **Hop-by-hop header smuggling.** Connection-managed headers (`Connection`, `Transfer-Encoding`, `Keep-Alive`, `Proxy-Authenticate`, etc.) pass through the gateway and confuse upstream or client connection handling. | The gateway **strips hop-by-hop headers** in both directions per the HTTP spec's connection-management rules; the upstream sees a clean, gateway-originated request. |
| 11 | **Secrets leakage.** Admin keys, Redis URLs with credentials, or upstream tokens end up in the repo, in logs, or in metrics. | Secrets come from the **environment only** (12-factor). `.env.example` documents the variable names with placeholder values and is the only env file committed. The **admin key is never committed**; a pre-commit/manual check keeps real `.env` files gitignored. Logs and metrics never print raw keys — key material appears only as hashed prefixes in admin output. |
